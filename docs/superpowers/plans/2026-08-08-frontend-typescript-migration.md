# Frontend Strict TypeScript Migration Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Convert every application-owned JavaScript/JSX module in the Next.js frontend to strict TypeScript without changing the existing UI or intended behavior.

**Architecture:** Establish strict compiler configuration first, then create narrow shared contracts for validation, Redux, RBAC, and reusable UI data. Convert modules from the dependency roots outward—utilities and state, shared components, feature components, then App Router pages—so every batch has a meaningful type-check gate.

**Tech Stack:** Next.js 14.2.15 App Router, React 18.3, TypeScript 5, Redux Toolkit 2.2, React Redux 9.1, redux-persist 6

## Global Constraints

- Preserve current routes, UI, styling, local-storage keys, API URLs, request formats, offline validation fallback, Redux behavior, and RBAC behavior.
- Use `strict: true`, `noEmit: true`, `allowJs: false`, and the Next.js TypeScript plugin.
- Do not use broad `any`, `@ts-ignore`, or `@ts-nocheck` migration escapes.
- Treat external JSON and caught errors as `unknown`, narrowing them before use when practical.
- Keep page-only types beside their pages and shared cross-cutting contracts in `types/`.
- Do not introduce a component-test framework solely for this migration; `npm run typecheck` and `npm run build` are the regression gates.
- The current workspace has no Git metadata. Each commit step is an intended checkpoint and must be run only if the project is placed in a Git repository before execution.

---

## File Structure

- `tsconfig.json`: strict Next.js compiler policy.
- `next-env.d.ts`: Next.js generated ambient type references.
- `types/validation.ts`: email validation result/check contracts.
- `types/rbac.ts`: roles, permissions, users, login results, and permission context contract.
- `types/ui.ts`: small shared option, toast, status, and table contracts used by multiple feature families.
- `store/store.ts`: configured store plus `RootState` and `AppDispatch`.
- `store/hooks.ts`: typed Redux hooks.
- Component-local prop interfaces remain in their `.tsx` files.

- [ ] **Step 4: Define RBAC contracts**

```ts
import type { ReactNode } from 'react';

export type RoleName = 'Super Admin' | 'Admin' | 'User' | 'Sub User' | 'Guest';
export type PermissionName = string;

export interface PermissionDefinition {
  id: string;
  name: PermissionName;
  module: string;
  label: string;
}

export interface RbacUser {
  id: string;
  name: string;
  email: string;
  role: Exclude<RoleName, 'Guest'>;
  role_id: string;
  permissions: PermissionName[];
}

export type AuthResult =
  | { success: true }
  | { success: false; error: string };

export interface PermissionContextValue {
  user: RbacUser | null;
  role: RoleName;
  permissions: PermissionName[];
  token: string | null;
  loading: boolean;
  availablePermissions: PermissionDefinition[];
  hasPermission(permission: PermissionName): boolean;
  canCreateRole(role: RoleName): boolean;
  getAllowedRolesToCreate(): Exclude<RoleName, 'Guest' | 'Super Admin'>[];
  login(email: string, password: string): Promise<AuthResult>;
  logout(): void;
  switchRoleDemo(role: RoleName): void;
  updateUser(fields: Partial<RbacUser>): void;
}

export interface ChildrenProps { children: ReactNode }
```

Use `createContext<PermissionContextValue | null>(null)`. Type authentication JSON through a local narrowing helper, keep the existing fallback messages, type the role rank as `Record<RoleName, number>`, and retain the guarded `usePermissionContext(): PermissionContextValue` return.
